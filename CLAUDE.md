# CLAUDE.md

Pipeline that collects MAVLab (TU Delft, Control & Simulation) publications into BibTeX and exports them for https://mavlab.tudelft.nl. See `README.md` for the data flow and the manual steps.

- Files starting with `# AUTOGENERATED` are overwritten by the import scripts; edit the scripts, not the output. Hand-maintained: `mediacoverage.bib`, `mavlab_nopure.bib`, `opensourcecode.json` (open-source code, format in `README.md`).
- The monthly GitHub Action (`.github/workflows/monthly_import.yml`) opens a PR when anything changed (import scripts exit 1 when incomplete, shown as a warning on the run); never commit directly to `master`, use a branch and a pull request.
- Scripts are run from the repo root (the website ones via `make -C website`).

## Website (https://mavlab.tudelft.nl)
WordPress with the teachPress plugin (9.0.12). The publication list on the website is maintained by hand in teachPress; this repo finds what is missing:
1. **Export what is online**: `make -C website download` (`website/download_website.py`) rebuilds `website/website_export.bib` from the public teachPress BibTeX feed (`https://mavlab.tudelft.nl/?feed=tp_pub_bibtex`): all publications and media items with their tags, the same entries as the teachPress export in wp-admin. `make -C website check-web` lists publications that are on the website twice; delete the copy that does not match git (by key or DOI), after pointing WordPress posts with `[tpsingle id=...]` to the copy that stays.
2. **Merge**: `make -C website` concatenates all local bib files into `website/all.bib` and runs `mavlab_bibtex_merge.py`, matching on DOI, then URL, then title + type + year. It ends with `check_duplicates.py` (also `make -C website check`, a warning in the monthly run): the same publication in two source files (e.g. a paper that is back in Pure but still in `mavlab_nopure.bib`) must be removed from the hand-maintained file; duplicates within `pure.bib` are Pure records for the library to merge.
3. **Result** (git-ignored files in `website/`):
   - `mavlab_pure_extra.bib`: local entries that are **not yet on the website** (the historical "pure only" list) -> import these in teachPress (wp-admin, teachPress > Import, BibTeX) with Author/Editor format **Default**: the preselected "dynamic" format drops name particles (`{de Croon}, G.` becomes `G. Croon`)
   - `mavlab_web_extra.bib`: on the website but not in this repo
   - `mavlab_merged.bib` / `mavlab_merged_web.bib`: matched pairs
4. After importing in teachPress, run step 1 and 2 again: `mavlab_pure_extra.bib` should be (nearly) empty.

The open-source code page: `make -C website code-page` writes `website/opensourcecode.html` from `opensourcecode.json`; WordPress loads it from GitHub master with the WPCode PHP snippet `website/wordpress/mavlab_github_include.php` (shortcode `[mavlab_github]`, cached 1 h, only `[tpsingle]` expanded). Papers are `[tpsingle key=...]`, so every paper key must be on the website.

teachPress exposes no REST route to list or add publications (only `teachpress/v1/autopublish/update_all`, which triggers its auto-publish import from configured BibTeX URLs; do not call it without asking). Never commit WordPress credentials or screenshots of them.

## Known issues
- **Pure import** (`import_pure_2021.py`): research.tudelft.nl puts a Cloudflare bot check in front of all pages, so the RSS feed and the publication pages cannot be downloaded (plain requests and headless Chrome both get "Just a moment..."). Do not try to bypass it; the official route is a read-only key for the Pure API (`pure.tudelft.nl/ws/api`, answers 401 without one), to be requested from the library. Every run is a full import into `pure/cs_import.bib` (git-ignored), a complete copy of Pure. It only replaces `pure/cs.bib` when the whole list was read and at most `MAX_REMOVED` papers are gone; otherwise it was a bad time to import (Pure often fails or temporarily drops papers): `pure/cs.bib` stays, the import is left for inspection, exit code 1. The papers that are gone are always listed.
- **arXiv import** (`import_arxiv_2021.py`) uses the official arXiv API (export.arxiv.org): author search plus batched metadata lookups, ~10 requests with 3 s pauses. It replaced one arxiv2bibtex.org request per paper, which got throttled after ~50 calls (#102). On failures it keeps the previous entries (and all previously found papers when a search fails) and its summary says to rerun. The output format matches arxiv2bibtex.
- **M.Sc. thesis import** (`import_repository.py`, #83): the repository's CSV export is gone; the importer uses the undocumented JSON endpoints of repository.tudelft.nl (`/search/data` for the list, `/api/record/uuid:<id>` for roles). `msc.bib` = a MAVLab member (staff, postdoc or PhD student, `mavlab_members.py`) as mentor/supervisor/coach, plus theses of other faculties (ME, EEMCS, ...) with MAVLab staff in any role (their mentor must be from the student's faculty, so the MAVLab daily supervisor is registered as graduation committee member); `msc_all.bib` = MAVLab staff in any role. Only theses with staff in the record count: across all of TU Delft a PhD student's last name + initial (Wu, Y.; Li, S.) often belongs to someone else. A run takes ~7 min (one record request per thesis). If the endpoints change, the previous entries are kept. Older MAVLab PhD theses often have no promotor in the repository, so PhDs still come from Pure.
- **MAVLab members** (`mavlab_members.py`): one list of staff, postdocs and PhD students (last name + first initials) for `filter_pure_mavlab.py` and `import_repository.py`; add new members there. The initials keep out other people with the same last name (J. Popovic, T.M. Croon, Y. Li, Meng Li); the `remove` list in `filter_pure_mavlab.py` is for the rest. Check `pure/cs_nomav.bib` and `pure.bib` after changes.
- `test/test.tex` references `arxiv` instead of `arxiv_nopub` and omits `msc` and `4tu`; `.travis.yml` (Python 2.6, trusty) is dead; `import_dataverse_2021.py` writes a stray `test.bib`; `website/reformat.py` and `old/` are legacy.
